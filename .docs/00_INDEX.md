# .docs 색인 — 도메인 정본

> 이 프로젝트가 **무엇을 다루는지**(업무 규칙·용어·데이터)의 정본. 하네스 운영 규칙은 `.harness/`, 과제별 요구는 `.harness/tasks/<id>/plan.md`.
> 쓰기: Opus·사람만 · 읽기: 모두(Codex 포함, 수정 금지). 새 문서를 만들면 아래 표에 한 줄 추가한다.

## 구조 (둘 중 하나로 시작)

**A. 작은 프로젝트 — 한 파일**
```
.docs/
  00_INDEX.md      ← 이 파일
  00_도메인.md     ← 도메인 전체
```

**B. 큰 프로젝트 — 폴더로 나눔** (`00_도메인.md`가 약 30KB를 넘거나 영역이 3개 이상이면)
```
.docs/
  00_INDEX.md
  00_도메인/            공통: 00-01_개요 · 00-02_용어 · 00-03_데이터 · 00-04_결정기록 …
  01_<영역>/            영역별 명세: 01-01_<주제>.md …
  02_<영역>/
```
A → B로 옮길 때: `00_도메인.md`의 장(§)을 `00_도메인/00-NN_*.md`로 나누고, 원래 파일은 지운다(정본은 하나).

## 규칙

- 파일명 `NN-MM_주제.md`, 폴더명 `NN_영역`. 00은 공통(도메인 전체), 01 이후는 영역.
- plan.md의 "참고 문서"에는 여기의 **경로와 §**를 적는다. Codex는 plan.md가 가리킨 문서만 근거로 쓴다.
- 결정이 바뀌면 옛 내용은 ~~취소선~~ + 「대체됨(날짜, 과제 id)」. 결정 기록은 지우지 않는다.
- 비공개 채점 기준(K 항목)은 여기에 쓰지 않는다 (guard가 차단).
